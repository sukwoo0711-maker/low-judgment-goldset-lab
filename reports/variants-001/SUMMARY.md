# 결정론적 질의 변형 001

## 결론

**기계적** 표면형 변형(띄어쓰기, 한/영 용어치환, 약어, 복합)만 결정론적 문자열 변환으로 옮겼습니다. **의미를 재서술하는 paraphrase는 모델 생성으로 남깁니다.** 기존에 수집된 fixture에서 자연 질의 1건당 평균 **4.33~6.0배**의 평가 질의가 추가 모델 호출 없이 생성됩니다.

이 단락은 변형 생성만 다룹니다. 1,000질의 실행과 4시간 soak는 여전히 미완이며 GPU 복구가 선행 조건입니다. 이 단락의 진전을 그 두 항목의 진전으로 읽으면 안 됩니다.

## 왜 바꿨는가

기존 후보 생성은 모델 한 번의 응답에서 `natural`, `mixed`, `spacing_abbreviation`, `paraphrase` **4종을 모두** 받아야 하고, 한 종이라도 형식을 어기면 후보 전체를 폐기합니다.

관측된 비용은 다음과 같습니다.

| 시도 결과 | 건수 | 비율 |
|---|---:|---:|
| valid | 49 | 19.5% |
| invalid | 159 | 63.3% |
| explicit_skip | 41 | 16.3% |
| error | 2 | 0.8% |
| 합계 | 251 | 100% |

출처: `full-candidates-v1` 시도 기록, 모델 `qwen2.5:7b`.

`invalid` 63.3%가 4종 요구 때문인지 다른 검증 항목 때문인지는 **현재 데이터로 귀속할 수 없습니다.** 시도 기록이 상태값만 남기고 원시 모델 출력이나 실패 사유를 보존하지 않기 때문입니다. 이 관측 불가 자체를 다음 gate의 수정 대상으로 기록합니다.

## 무엇을 결정론화했고 무엇을 남겼는가

`query_variants` 모듈은 승인된 용어 사상표를 이용해 자연 질의 하나에서 아래 변환을 적용합니다. 변환은 순수 함수이고 seed·모델·네트워크를 쓰지 않습니다.

| transform_id | 무엇을 측정하는가 | 무엇이 이 변형을 무력화하는가 |
|---|---|---|
| `spacing.join_all` | 띄어쓰기 없는 질의 정합 | subword 또는 n-gram 색인 |
| `spacing.pad` | 공백 정규화 | 공백 정규화 |
| `mixed.ko_to_en` | 한→영 용어 교차 정합 | 이중언어 용어사전 |
| `mixed.en_to_ko` | 영→한 용어 교차 정합 | 이중언어 용어사전 |
| `abbreviation.apply` | 약어 정합 | 약어 확장 |
| `compound.ko_to_en_join` | 혼합 표기이면서 띄어쓰기까지 소실된 복합 질의 | 이중언어 용어사전 + subword 색인 |

각 변형은 **무엇을 탐침하고 무엇에 의해 무력화되는지**를 함께 기록합니다. 실패가 "패러프레이즈에 약함" 같은 모호한 진술이 아니라 이름 붙은 결함으로 떨어집니다.

**결정론화하지 않은 것**: 사용자가 요구한 세 축 중 "같은 의미지만 다른 표현"은 통사 구조가 바뀌는 재서술이며, 위 변환은 전부 어휘 치환이거나 공백 조작이라 이것을 만들지 못합니다. 사전 치환을 paraphrase라고 부르면 요구사항의 정의를 조용히 바꾸는 것이 됩니다. 따라서 `paraphrase`는 모델 생성으로 유지합니다.

모델의 형식 요구를 4종에서 `natural` + `paraphrase` 2종으로 낮추는 것은 **이번 단락에서 하지 않았습니다.** 4종 구조가 최소 5곳에 하드코딩되어 있어 함께 고치지 않으면 파이프라인이 전부 실패합니다: `fixture_builder`의 SYSTEM 프롬프트, `_parse_candidate`의 4종·라틴문자·대문자 요구, 기존 fixture 클러스터 완전성 검사, `contracts.validate_mode_count`의 4의 배수 제약, `review.py`의 클러스터당 4질의 조건.

### 사람 판단이 줄어드는 지점과 줄지 않는 지점

변형은 부모 질의의 `fact_cluster_id`와 라벨, provenance를 그대로 상속합니다. 표면형만 바뀌고 의미는 사상표에 의해 보존되므로 변형마다 새로 판정할 것이 없습니다.

그러나 **판단이 사라진 것은 아닙니다. 판단의 단위가 바뀐 것입니다.**

표면형 축에 한해 판단 단위가 **질의당**에서 **용어당 + 변환당 표본**으로 바뀝니다. 구체적으로 판단은 두 곳에 남습니다.

1. **용어 사상표 승인.** 현재 상태는 `draft_unverified`이며, 로더는 승인되지 않은 사상표로 채점 실행하는 것을 거부합니다. 진단용 dry run만 `allow_unapproved`로 허용됩니다. 일반어 겸용 12개는 개별 판단이 필요합니다.
2. **변환 단위 표본 검토.** 파생 변형은 기존 검토 도구의 질의별 "자연스러운 표현입니까?" 확인을 거치지 않습니다. 결정론적 변환은 규칙이 균일하므로 표본은 개별 행이 아니라 **규칙을 검정**합니다. 설계는 다음과 같습니다.
   - 표본은 클러스터가 아니라 `transform_id` 단위로 층화하고, 변환마다 seeded 결정론 표본 `min(20, 전체)`을 뽑는다.
   - 표본 ID 목록과 seed를 review manifest에 기록한다.
   - 합격 기준: 표본 내 `N` 0건(`U`는 2건까지 허용).
   - `N`이 1건이라도 나오면 행을 고치지 않고 **해당 변환의 전체 행을 그 실행의 채점에서 제외**한다. 결함은 행이 아니라 규칙에 있기 때문이다.
   - 의미 협소화·비현실 표면 위험이 가장 큰 `compound.ko_to_en_join`과 `abbreviation.apply`는 매 실행 표본에 강제 포함한다.
   - 파생 행 라벨은 `decision_source="deterministic"`으로 기록해 사람 Y로 위장하지 않는다.
   - 표본 20건 무결함의 95% 신뢰상한 실패율은 약 14%다. 따라서 보고서에는 **"규칙이 체계적으로 깨지지 않았음"까지만** 쓰고 행 단위 품질은 주장하지 않는다.

이 표본 설계는 아직 구현되지 않았습니다. 아래 "파이프라인 연결 상태"를 참조하십시오.

## 1차 심문에서 드러난 결함과 수정

이 단락의 초안은 표면형 변형을 **전부** 결정론화하려 했고, 독립 비판자 3명이 전원 이를 기각했습니다. 실행으로 재현된 결함은 다음과 같습니다.

| 입력 | 초안의 산출 | 원인 |
|---|---|---|
| `scroll of protection details` | `sc굴림 of protection details` | 라틴 용어에 단어경계 없음 |
| `casting time` | `시전ing time` | 라틴 용어에 단어경계 없음 |
| `피해망상 사건` | `damage망상 사건` | 한글은 정규식 `\b`가 성립하지 않음 |
| `우위를 점하는 방법` | `advantage를 점하는 방법` | 일반어를 도메인 용어로 오치환 |

적용한 수정입니다.

- **형태소 경계 규칙.** 한국어 조사 폐쇄목록을 선택적으로 매치해 치환 후 다시 붙이고, 앞뒤가 한글이면 매치하지 않습니다. 라틴 용어는 앞뒤 영숫자를 금지합니다. `피해를 계산` → `damage를 계산`은 되고 `피해망상`은 손대지 않습니다.
- **무결성 검사.** 치환 결과에 라틴↔한글 융합이 생기면(조사 부착은 예외) 변형을 폐기합니다. 손상된 질의를 만들어 통과시키는 대신 만들지 않습니다.
- **일반어 표시.** 도메인 밖에서도 흔히 쓰이는 12개 용어(주문·이점·불리점·집중·공포·중독·은신·기습·저항·취약·면역·피해)에 `generic_risk`를 붙이고 기본 제외했습니다. 명백한 일반어 별칭(약점·불리·우위)은 삭제했습니다.
- **스키마 정렬.** 파생 행이 실행기와 같은 필드명(`question_id`/`query`/`query_kind`)을 쓰고 부모 행 전체를 상속합니다. 이전 초안은 필드명이 달라 파이프라인에 연결되지 않았습니다.

위 4개 손상 사례는 재실행 결과 변형을 **아예 생성하지 않습니다.**

### 용어 치환은 사실상 고유명사 하나가 만든다

`mixed.ko_to_en` 44.9%를 "도메인 용어 커버리지"로 읽으면 안 됩니다. 항목별로 쪼개면 다음과 같습니다.

| 사상표 항목 | 발화 질의 |
|---|---:|
| 발더스 게이트 3 → Baldur's Gate 3 | 21 |
| 선제권 → initiative | 1 |
| 능력치 → ability score | 1 |
| 나머지 활성 표면 19개 | **0** |

활성 한국어 표면 24개 중 **19개는 한 번도 발화하지 않았습니다.** 발화 22건 중 21건이 게임 제목 한 항목입니다. 즉 이 코퍼스에서 교차언어 변형이 실제로 검정하는 것은 도메인 용어집이 아니라 **고유명사 하나의 표기 정합**에 가깝습니다.

이 때문에 단일 지표 "용어 적중률"은 보고서에서 쓰지 않습니다. 배수 4.33×를 실제로 지탱하는 것은 띄어쓰기 계열 두 변환(각 100%)입니다.

### 안전 조치의 비용

일반어 12개를 제외하고 경계 규칙을 넣은 대가는 다음과 같습니다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 활성 한국어 표면 | 39 | 24 |
| 확장 배수(49질의) | 4.49× | 4.33× |
| `mixed.ko_to_en` 발화 질의 | 26 | 22 |

표면 어휘를 38% 줄였는데 배수는 3.6%만 감소했습니다. 제외된 용어들이 만들던 변형의 상당 부분을 띄어쓰기 계열이 이미 담당하고 있었기 때문입니다. **안전 조치의 비용이 작다는 뜻이며, 반대로 초안의 배수 4.49× 중 손상·오치환 위험이 있는 몫이 있었다는 뜻이기도 합니다.**

## 이 숫자가 말하지 않는 것

- **`mixed.en_to_ko` 0%**는 버그가 아니라 코퍼스 성질입니다. 현재 자연 질의가 전부 한국어라 되돌릴 영어 용어가 없습니다. 이 변환은 지금 코퍼스에서 휴면 상태이며, 사용자가 영어 용어를 섞어 입력하는 회사 PC 환경에서 활성화됩니다. 초안의 단어경계 결함이 정확히 이 변환에서 터졌으므로, 활성화 시점과 결함 노출 시점이 같았을 것입니다.
- **용어 사상표 적중률 44.9%**는 나머지 절반의 질의가 띄어쓰기 계열 변형만 받는다는 뜻입니다. 배수는 사상표 어휘 범위에 직접 묶여 있습니다.
- 배수는 **평가 질의 수**의 증가일 뿐 독립 사실 수의 증가가 아닙니다. 변형은 부모와 같은 `fact_cluster_id`를 공유하므로 신뢰구간은 cluster 단위로 계산해야 하며, 질의 수로 신뢰도를 부풀리면 안 됩니다.
- 모델 요구를 2종으로 낮추면 유효율이 어떻게 되는지는 **이 보고서가 주장하지 않습니다.** `invalid` 63.3%의 사유 귀속이 없는 상태에서 2종화 후 수치가 좋아져도 그 개선을 원인에 귀속할 수 없습니다. 사유 로깅이 먼저입니다.
- 변형 질의에 대한 검색·생성 성능은 측정하지 않았습니다. 이 단락은 질의 생성까지입니다.

## 회사 PC 이식에서 무엇이 옮겨가는가

용어 사상표 28항목은 전부 D&D 게임 용어이고 도메인이 `bg3-public-wiki`로 고정되어 있습니다. 회사 PC의 실제 대상(사양서·결함이력)으로 옮기면 **이 항목들의 재사용률은 0입니다.** 게다가 사내 용어 사상표는 저장소 계약상 이 공개 저장소에 넣을 수 없습니다.

이식되는 것과 그렇지 않은 것을 나누면 다음과 같습니다.

| 항목 | 이식 여부 |
|---|---|
| 변환 함수, 조사 경계 규칙, 무결성 검사, QA 투영, 스키마 | 이식됨 (도메인 무관) |
| 승인 절차와 표본 설계 | 이식됨 |
| 사상표 내용 28항목 | **이식 안 됨.** 전부 D&D 용어이며 사양서·결함이력에 재사용 0 |

사내 도메인 사상표는 계약 7조("사내 데이터는 공개 저장소에 기록하지 않는다")에 따라 이 저장소에 커밋하지 않고 `--term-map` 인자로만 외부에서 주입합니다. 사고 방지를 위해 `load_term_map`이 실행 manifest가 선언한 도메인과 사상표의 `domain`이 불일치하면 거부하도록 하는 것이 다음 gate입니다.

따라서 절감 주장은 다음 형태로만 유효합니다. **표면형 축에 한해 판단 단위가 질의당에서 용어당 + 변환당 표본으로 바뀐다.** 절감은 도메인 전환마다 리셋되고, 한 도메인 안에서 질의 수가 많을수록 이득이 커집니다. 다만 이 코퍼스에서 실제로 값을 만든 사상표 항목은 활성 16개 중 3개뿐이므로, 현 데이터는 이 절감 구조의 근거로 얇습니다. 회사 PC의 사양서 어휘가 BG3보다 폐쇄적·반복적이라 유리할 것으로 예상하지만 측정된 바 없습니다.

## 파이프라인 연결 상태 — 아직 연결되지 않았습니다

`query_variants`는 현재 **어떤 실행 경로에도 연결되어 있지 않습니다.** 파생 행이 공개 fixture 검증(`validate_public_fixture`)은 359건 전량 통과하지만, 그 외 게이트 셋이 확장 세트를 거부합니다.

| 게이트 | 위치 | 왜 거부하는가 |
|---|---|---|
| 사례 수 4의 배수 | `contracts.py` `validate_mode_count` | 확장 세트는 질의당 변형 수가 달라 4의 배수가 아니다 |
| 클러스터당 질의 정확히 4개 | `review.py` 승인 조건 | 확장 클러스터는 5개 이상이라 승인되지 않는다 |
| 모든 질의에 사람 `Y` | `report.py` full gate | 파생 행에는 사람 판정이 없어 full report가 실패한다 |

즉 파생 변형은 "사람 검증을 우회"하는 상태가 아니라 **계약 개정 전에는 기능 자체가 불가능한** 상태입니다. 이 게이트들은 누수를 막고 있지만 동시에 기능도 막고 있습니다. 위 표본 설계와 `query_derived` 라벨 타입을 계약에 추가하기 전에는 확장 세트를 채점 실행에 쓰지 않습니다.

QA 입력 투영은 이번에 추가했습니다. `variant_rows`는 부모 행 전체(정답·predicate·provenance 포함)를 상속하므로 그대로 모델에 넣으면 oracle 누수입니다. `qa_input_rows`가 실행기 허용 5키(`question_id`, `fact_cluster_id`, `query`, `query_kind`, `fixture_run_fingerprint`)로만 투영합니다.

## 평가 누수 경계

변형에 쓰는 용어 사상표가 검색기의 glossary 확장과 같으면, 혼합 변형은 검색기가 아니라 사전을 측정합니다.

현재 이 통제에는 결함이 둘 있고, 둘 다 이번 단락에서 고치지 않았습니다.

1. **연결되지 않음.** `glossary_overlap`은 테스트 외에 호출되는 곳이 없습니다. 보고서 생성 경로가 이 값을 싣지 않습니다. "보고서 계약에 명시"는 아직 문서 문장일 뿐입니다.
2. **지표가 둔감함.** `trivially_solvable`은 24개 표면이 **전량** 겹칠 때만 켜집니다. 그런데 실측상 검색기가 게임 제목 하나만 알아도 혼합 변형 22건 중 21건이 무력화되는데, 겹침 비율은 1/24 ≈ 4%로 표시됩니다. 현 지표는 실제 무력화 상태를 탐지하지 못합니다.

교체 계획: 항목 수 기준 비율 대신 **발화 가중** 지표를 쓴다. `effective_overlap = (치환 용어가 검색기 glossary에 있는 변형 행 수) / (전체 혼합·복합 변형 행 수)`. 임계값 초과 시 run manifest에 `cross_lingual_claim_prohibited`를 기록하고 보고서의 교차언어 강건성 절을 렌더링하지 않는다.

**적용 시점**: 현재 검색기는 BM25 단일 arm이고 glossary arm이 구현되어 있지 않습니다(`retrieval.py`). 따라서 이 누수는 현재 실행에는 발생하지 않으며, 회사 PC의 하이브리드 검색기를 도입하는 시점의 선행 조건입니다.

## 검증

- 테스트 36개 → **52개 통과**, 실행 0.33초, GPU·네트워크·외부 패키지 불필요(stdlib `unittest`)
- 신규 테스트: 사상표 검증 실패, 최장 일치 우선, 라틴 단어 내부 미치환, 한글 단어 내부 미치환, 조사 보존, 스크립트 융합 탐지, 일반어 기본 제외, 결정성, 라벨·provenance 상속, QA 투영의 oracle 필드 제거, glossary 겹침 판정
- 통합 확인: 기존 fixture 196행을 확장한 359행이 `validate_public_fixture`를 전량 통과(실패 0), `question_id` 유일, 사실군 집합 보존
- 실행 방법: `PYTHONPATH=src python -m unittest discover -s tests` (README와 동일한 경로)

## 다음 gate

순서가 중요합니다. 1번을 건너뛰고 2번을 하면 개선분을 원인에 귀속할 수 없습니다.

1. 후보 생성 실패에 사유를 기록해 `invalid` 63.3%를 항목별로 귀속한다. GPU 불필요(로깅), 측정은 GPU 필요.
2. 계약을 개정해 확장 세트를 받아들인다: `validate_mode_count`의 4의 배수 제약, `review.py`의 클러스터당 4질의 조건, `report.py` full gate의 질의별 사람 `Y` 요구, `ATOMIC_TARGET_TYPES`에 `query_derived` 추가.
3. 변환 단위 층화 표본 검토를 구현한다(seed 기록, `N` 0건 합격, 실패 시 변환 단위 격리).
4. `spacing.pad`를 전량 적용에서 표본 적용으로 낮춘다. 현재 확장 세트 212행 중 49행(23.1%)을 차지하며, 1,000건 기준 약 231질의의 추론 예산에 해당한다. 표본에서 1건이라도 실패하면 다음 실행에서 전량 적용으로 승격한다.
5. `load_term_map`에 도메인 일치 검증을 추가해 사내 사상표를 다른 도메인 실행에 잘못 물리는 사고를 차단한다.
6. 용어 사상표를 공식 한국어 표기와 대조해 승인 상태로 올린다. 일반어 12개는 개별 판단이 필요하다.
7. 모델 요구를 `natural` + `paraphrase` 2종으로 낮춘 뒤 동일 청크에서 유효율을 재측정한다. GPU 필요. 2종화는 `fixture_builder`의 프롬프트와 `_parse_candidate`의 4종·라틴문자·대문자 요구, 기존 fixture 완전성 검사를 함께 고쳐야 한다.
8. glossary 겹침을 발화 가중 지표로 교체하고 실행 경로에 연결한다. 하이브리드 검색기 도입 시점의 선행 조건.
9. 변형별 검색 성공률을 측정해 어떤 정규화가 없는지 이름으로 확인한다. GPU 필요.
