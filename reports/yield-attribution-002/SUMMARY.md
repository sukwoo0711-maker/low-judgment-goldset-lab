# 수율 손실 귀속 002

## 결론

후보 생성 실패에 **사유 코드**를 붙였습니다. 앞으로의 실행은 `invalid`를 단일 덩어리가 아니라 게이트별로 기록합니다.

과거 실행의 63.3%는 원시 모델 출력이 보존되지 않아 소급 귀속할 수 없습니다. 대신 통과한 후보로 게이트를 역추적하다가 **설계 모순 하나와 죽은 분기 하나**를 찾았습니다.

- 스키마는 띄어쓰기 변형을 요구하는데, **다른 게이트가 그것의 순수한 형태를 수학적으로 금지합니다.** 순수 띄어쓰기 변형은 어떤 실행에서도 통과할 수 없습니다.
- `spacing_abbreviation` 통과 조건 셋 중 `BG3` 분기는 도달 불가능한 죽은 코드입니다.

## 사유 코드

`_parse_candidate_with_reason`이 어느 게이트가 후보를 버렸는지 반환하고, 시도 기록에 `reasons` 배열(패스별 1개)로 남습니다.

| 사유 코드 | 무엇을 어긴 것인가 |
|---|---|
| `ok` | 통과 |
| `explicit_skip` | 모델이 근거 부족으로 생성을 거부 |
| `missing_reference_answer` | 기준답이 없거나 공백 |
| `missing_predicate` | 필수 사실이 없거나 공백 |
| `queries_not_four` | 질의 배열이 4개가 아님 |
| `query_item_malformed` | 항목이 객체가 아니거나 `kind`가 미정의 |
| `kinds_incomplete` | 4개이지만 종류가 중복되어 4종을 못 채움 |
| `empty_query_text` | 질의 문자열이 공백 |
| `duplicate_query_text` | 공백 무시 후 같은 질의가 둘 이상 |
| `mixed_has_no_latin` | 혼합 질의에 라틴 문자가 없음 |
| `spacing_has_no_marker` | 띄어쓰기·약어 질의에 대문자 2자 이상도, 이중 공백도 없음 |
| `duplicate_of_previous_pass` | 파싱은 됐으나 1차 패스와 같은 사실 |

`duplicate_of_previous_pass`는 파싱 실패가 아니라 중복이므로 별도로 셉니다. 기존 구조에서는 "모델이 형식을 못 맞춘다"와 "모델이 같은 사실만 반복한다"가 같은 통에 들어갔습니다.

## 설계 모순 — 띄어쓰기 변형은 통과할 수 없다

`duplicate_query_text` 검사는 네 질의를 **공백을 전부 제거하고** 비교합니다.

```python
normalized_texts = {re.sub(r"\s+", "", item["text"]).casefold() for item in normalized}
if len(normalized_texts) != 4:
    return None, "duplicate_query_text"
```

`spacing_abbreviation` 질의가 자연 질의를 **단어는 그대로 두고 띄어쓰기만 바꾼 것**이면, 공백 제거 후 두 문자열은 반드시 같아집니다. 집합 크기가 3이 되어 후보 전체가 폐기됩니다. 예외가 아니라 항상 그렇습니다.

실행으로 확인했습니다. `내성 굴림은 어떻게 판정하나`에 대한 `내성굴림은  어떻게판정하나`는 `duplicate_query_text`를 반환합니다. 회귀 테스트로 고정했습니다.

**결과적으로, 승인된 어떤 fixture에도 순수 띄어쓰기 변형은 존재할 수 없습니다.** 이것은 관측이 아니라 구성상 증명입니다. 사용자가 명시한 세 축 중 띄어쓰기 축은 모델 생성 경로에서 만들어질 수 없는 상태였습니다.

## 죽은 분기 — `BG3` 조건은 도달 불가능하다

`spacing_has_no_marker` 게이트는 세 조건의 OR로 쓰여 있습니다: `[A-Z]{2,}`, `\bBG3\b`, 이중 공백.

그런데 `BG3`의 `BG`가 이미 `[A-Z]{2,}`에 걸립니다. 대문자 `BG3`를 담은 질의는 첫 조건에서 통과하고, 소문자 `bg3`는 두 조건 모두에 걸리지 않습니다. `\bBG3\b`는 독자적으로 발화할 수 없습니다.

실질 조건은 **둘**입니다: 대문자 2자 이상, 또는 이중 공백.

## 게이트 취약도 역추적

과거 실행에서 **통과한** 후보 49건이 각 조건을 어떻게 만족했는지 측정했습니다.

### `spacing_abbreviation` 통과 경로

| 통과 경로 | 건수 | 비율 |
|---|---:|---:|
| 대문자 2자 이상만 | 29 | 59.2% |
| 대문자 2자 이상 + `BG3` 포함 | 17 | 34.7% |
| 이중 공백 | 3 | 6.1% |

두 번째 행은 별개 경로가 아니라 첫 번째 조건으로 통과한 것 중 `BG3`를 담고 있던 것입니다(위 죽은 분기 참조). 그 17건 중 16건은 대문자 표지가 `BG3` 하나뿐입니다. 즉 **46건(93.9%)이 대문자·약어로 통과**했습니다.

이중 공백 3건도 "순수 띄어쓰기 변형"이 아닙니다. 순수 변형은 위에서 보듯 통과가 불가능하므로, 이 3건은 **어휘도 함께 바뀐 질의가 우연히 이중 공백을 포함한 것**입니다.

### `mixed` 통과 강도

혼합 질의의 게이트 조건은 라틴 문자 **1자** 이상입니다(`re.search(r"[A-Za-z]", mixed)`). 통과 사례의 라틴 토큰 수 분포입니다. 토큰은 정규식 `[A-Za-z]+`의 연속 구간으로 셌으며, 이는 게이트 조건보다 엄격한 별도 집계 기준입니다.

| 라틴 토큰 수 | 건수 |
|---:|---:|
| 1 | 24 |
| 2 | 9 |
| 3 | 4 |
| 4 이상 | 12 |

49건 중 24건(49.0%)이 라틴 토큰 하나로 통과했습니다.

## 이 결과가 설계에 주는 의미

1. **띄어쓰기 축은 결정론적 변환이 담당해야 합니다.** 근거는 "모델이 안 만든다"가 아니라 "현재 계약에서는 만들 수 없다"입니다. `duplicate_query_text`를 완화해 순수 띄어쓰기 변형을 허용하는 방법도 있지만, 그러면 서로 다른 사실을 요구하는 중복 방지 기능이 함께 약해집니다. 띄어쓰기 축을 모델 요구에서 빼고 [변형 001](../variants-001/SUMMARY.md)의 결정론적 변환에 넘기면 중복 검사를 엄격하게 유지한 채 축을 살릴 수 있습니다.
2. **`spacing_abbreviation`이라는 단일 종류가 두 축을 섞고 있습니다.** OR 조건이라 모델은 통과 가능한 쪽(약어)만 고르게 되며, 다른 쪽은 애초에 통과 불가입니다. 종류를 분리하지 않으면 이 사실이 집계에 드러나지 않습니다.
3. **혼합 축의 강도를 기록해야 합니다.** 게이트가 라틴 1자만 요구하므로 강도가 통제되지 않습니다. 치환된 용어 수를 남기면 강도별로 성적을 나눌 수 있습니다.

## 이 결과가 말하지 않는 것

- 과거 `invalid` 63.3%의 게이트별 분포는 **여전히 알 수 없습니다.** 위 분석은 통과 사례에서 얻은 간접 증거이고 생존 편향이 있습니다. 편향의 방향도 단순하지 않습니다 — 띄어쓰기 경로는 구조적으로 봉쇄되어 있어 관측된 6.1%가 모델 성향의 하한조차 되지 못합니다. 직접 귀속은 사유 코드를 켠 상태로 GPU 복구 후 재실행해야 얻어집니다.
- **결정론적 변환의 "적용률 100%"와 모델 경로의 "6.1%"를 나란히 비교하면 안 됩니다.** 앞의 값은 공백이 있으면 항상 성립하는 정의상 보장값이고, 뒤의 값은 결합 검증과 봉쇄 게이트를 모두 통과한 생존자 비율입니다. 두 수치는 같은 종류의 양이 아니며, 이전 판(이 보고서의 초안)이 이 둘을 비교해 "배수보다 강한 근거"라고 쓴 것은 철회합니다.
- **라틴 토큰 1개를 "약한 혼합"이라고 판정할 외부 근거가 없습니다.** 게임 커뮤니티의 실제 코드스위칭은 단어 하나 치환이 지배적일 수 있습니다(예: "AC 얼마임?"). 강도 분포는 기록하되, 실사용 대비 강약 판단은 실제 사용자 질의 표본을 얻기 전까지 하지 않습니다.
- 표본은 후보 49건, 모델은 `qwen2.5:7b` 하나입니다.
- 결정론적 변환이 검색 품질을 실제로 진단하는지는 측정되지 않았습니다. 유용성 판정은 "적용률"이 아니라 검색기를 실제로 무력화하는지(발화 가중 겹침, 변형별 검색 성공률)로 해야 하며 GPU가 필요합니다.

## 검증

- 테스트 52개 → **60개 통과**, stdlib `unittest`, GPU·네트워크·외부 패키지 불필요
- 신규 테스트: 게이트 9종의 사유 코드 각각, 종류 중복과 항목 오류의 분리, 중복 사실이 `duplicate_of_previous_pass`로 기록되는지, 얇은 래퍼 호환, **순수 띄어쓰기 변형이 반드시 `duplicate_query_text`가 되는 모순**, `BG3` 분기 도달 불가
- 실행 방법: `PYTHONPATH=src python -m unittest discover -s tests`
