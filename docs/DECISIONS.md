# 결정 기록

## D001 — 평가 branch와 로컬 QA branch 분리

판정: `accept after revision`

웹 검색 결과가 로컬 검색 질의나 동의어에 유입되면 평가 누수가 생깁니다. 공개 reference는 fixture 제작에만 사용하고, 로컬 QA에는 자연 질의만 전달합니다. 별도 입력 root와 hash allowlist를 사용하고 canary token으로 누수를 자동 검사합니다.

## D002 — 사람 입력을 Y/N/U로 제한

판정: `accept after revision`

질문 전체를 한 번에 채점하지 않고 predicate·claim·인용·기권을 원자 단위로 순차 판정합니다. 도구가 predicate와 claim 후보를 만들고 사람은 `Y/N/U`와 고정 사유만 고릅니다. 선행 판정에 따라 불필요한 질문을 생략하고 Undo와 판정 시간 측정을 제공합니다.

## D003 — 기존 검색 결과로 goldset 자동 생성

판정: `reject as oracle`

현재 검색기가 찾은 문서를 그대로 expected로 삼으면 그 검색기의 어휘와 실패를 정답에 복제합니다. 자동 채굴 결과는 lexical·dense·entity·oracle·random/hard-negative pool 중 하나의 후보로만 사용하며 provenance를 숨긴 검토와 held-out 분리를 요구합니다.

## D004 — 기계적 표면형 변형만 결정론화하고 paraphrase는 모델에 남김

판정: `accept after revision`

**검토 대안**: (A) 현행대로 모델이 4종 전부 생성 / (B) 표면형 변형 전면 결정론화 / (C) 기계적 변형만 결정론화하고 의미 재서술은 모델 유지 / (D) 변형 포기.

**초안은 B였고 기각되었습니다.** 독립 비판자 3명이 blind로 전원 C를 추천했고, 제안자의 선택은 비판자에게 전달되지 않았습니다.

**최강 공격과 검증 결과**: 어휘 치환에 단어경계 처리가 없어 문자열이 손상됩니다. 실행으로 재현했습니다 — `scroll of protection` → `sc굴림 of protection`, `casting time` → `시전ing time`, `피해망상 사건` → `damage망상 사건`, `우위를 점하는 방법` → `advantage를 점하는 방법`. 또한 구현된 변환은 전부 어휘 치환이거나 공백 조작이라 통사 구조가 바뀌는 "같은 의미지만 다른 표현"을 만들지 못합니다. B는 요구사항의 한 축을 삭제하는 제품 정의 변경입니다.

**채택안**: C. 조사 폐쇄목록 기반 형태소 경계 규칙, 라틴↔한글 융합 무결성 검사, 일반어 겸용 용어 12개 기본 제외, 실행기 필드명 정렬과 QA 입력 5키 투영을 추가했습니다. `paraphrase`는 모델 생성으로 유지합니다. 재실행 결과 위 4개 손상 사례는 변형을 생성하지 않습니다.

**판정 주체**: 신선한 판정자 1명이 익명 패킷으로 쟁점 6건을 판정(전건 `수정 채택`, 종합 `조건부 가능`). 판정자가 제안자와 비판자가 모두 놓친 사실을 발견했습니다 — `mixed.ko_to_en` 발화 22건 중 21건이 게임 제목 한 항목이고 활성 표면 24개 중 19개는 한 번도 발화하지 않습니다. 이에 따라 단일 지표 "용어 적중률"을 보고서에서 삭제하고 항목별 발화 표로 교체했습니다.

**신뢰도**: 중간. 손상 결함은 실행으로 방어·수정이 확인되었으나, 변형이 검색 품질을 실제로 진단하는지는 GPU 복구 전까지 측정할 수 없습니다. 제안자·비판자·판정자가 같은 모델의 상관 표본이라는 한계도 남습니다.

## D005 — 파생 변형은 전수 사람 검토 대신 변환 단위 표본으로 검정

판정: `accept after revision` (조건부, 미구현)

결정론적 변환은 규칙이 균일하므로 표본은 개별 행이 아니라 규칙을 검정합니다. 표본은 `transform_id` 단위로 층화하고 변환마다 seeded 결정론 표본 `min(20, 전체)`을 뽑습니다. 합격 기준은 표본 내 `N` 0건(`U`는 2건까지)이며, `N`이 1건이라도 나오면 행을 고치지 않고 해당 변환의 전체 행을 그 실행 채점에서 제외합니다. 파생 행 라벨은 `decision_source="deterministic"`으로 기록해 사람 `Y`로 위장하지 않습니다.

표본 20건 무결함의 95% 신뢰상한 실패율은 약 14%입니다. 따라서 "규칙이 체계적으로 깨지지 않았음"까지만 주장하고 행 단위 품질은 주장하지 않습니다.

이 설계는 아직 구현되지 않았고, 계약 개정(4의 배수 제약, 클러스터당 4질의 조건, full gate의 질의별 사람 `Y`, `query_derived` 라벨 타입)이 선행되어야 합니다. 그 전까지 확장 세트는 채점 실행에 쓰지 않습니다.

## D006 — 후보 생성 실패에 사유 코드를 기록

판정: `accept`

`invalid` 63.3%가 어느 검증 항목에서 발생했는지 알 수 없었습니다. 시도 기록이 상태값만 남기고 원시 출력이나 실패 사유를 보존하지 않았기 때문입니다. `_parse_candidate_with_reason`이 게이트 이름을 반환하고 시도 기록에 `reasons`로 남깁니다. 파싱 실패와 "1차 패스와 같은 사실"은 원인이 다르므로 `duplicate_of_previous_pass`로 분리했습니다.

과거 데이터의 소급 귀속은 불가능합니다. 사유 코드는 다음 실행부터 유효합니다.

## D007 — 띄어쓰기 축을 모델 요구에서 제거

판정: `accept after revision`

**발견**: 스키마는 `spacing_abbreviation` 질의를 요구하는데, `duplicate_query_text` 검사가 네 질의를 공백 제거 후 비교하므로 **단어를 그대로 두고 띄어쓰기만 바꾼 질의는 반드시 중복으로 판정되어 후보 전체를 폐기시킵니다.** 순수 띄어쓰기 변형은 승인된 어떤 fixture에도 존재할 수 없습니다. 이것은 측정이 아니라 구성상 증명이며 회귀 테스트로 고정했습니다.

부수 발견: 같은 게이트의 `\bBG3\b` 분기는 `[A-Z]{2,}`가 `BG3`의 `BG`를 이미 매치하므로 도달 불가능한 죽은 코드입니다.

**검토 대안**: (A) `duplicate_query_text`를 완화해 띄어쓰기 변형을 허용 / (B) 띄어쓰기 축을 모델 요구에서 빼고 결정론적 변환(D004)에 넘김.

**채택**: B. A는 서로 다른 사실을 요구하는 중복 방지 기능을 함께 약화시킵니다. B는 중복 검사를 엄격하게 유지한 채 축을 살립니다.

**심문 기록**: 이 결정은 비판자 2명(측정 타당성, 사용자 대변)의 축소 grill에서 나왔습니다. 판정자는 두지 않았습니다 — 비판자들의 지적이 서로 수렴했고 제안자가 방어하지 않고 인정했기 때문입니다. **초안의 해석 두 가지를 철회했습니다**: (1) "모델이 띄어쓰기 변형을 만들지 않는다"는 관측은 틀렸고, 실제로는 게이트가 봉쇄하고 있었습니다. (2) "결정론적 변환 100% 대 모델 6.1%"라는 비교는 정의상 보장값과 생존자 비율을 나란히 놓은 것이라 성립하지 않습니다.

**신뢰도**: 중간. 모순 자체는 코드로 증명되었으나, 축을 옮긴 뒤 실제 검색 진단력이 개선되는지는 GPU 복구 전까지 측정할 수 없습니다. 독립 리뷰는 비판자 2명으로 축소했으며 판정자를 두지 않았습니다.
